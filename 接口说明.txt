MicroHX 接口使用说明
一、登录态说明
本 SDK 使用 Cookie 维持用户登录状态。
使用前需要用户自行抓取已登录状态下的 Cookies，然后通过：
    update_auth(cookies)
更新对象登录态。
示例：
    hx = MicroHX()
    hx.update_auth(
        "PHPSESSID=xxxxxxxxxxxx"
    )
更新成功后，后续接口会自动携带该登录信息。
==================================================
二、接口说明
1. test_auth()
功能：
    测试当前登录状态是否有效。
用途：
    在调用其他需要登录的接口前，可以先检测 Cookies 是否失效。
返回：
    True
        当前登录有效
    False
        当前登录失效，需要重新更新 Cookies
==================================================
2. api_getvisitedactives()
功能：
    获取用户已经参加过的活动列表。
接口用途：
    查询当前账号历史参与的活动信息。
返回：
    接口原始 JSON 数据。
==================================================
3. api_sumhdxfforxflx()
功能：
    获取用户当前已获得的活动学分。
接口用途：
    查询账号活动学分累计情况。
返回：
    接口原始 JSON 数据。
==================================================
4. api_ssyx(price)
功能：
    宿舍预选接口。
参数：
    price
        宿舍价位参数。
        可选值：
            "1500"
            "3000"
            "4000"
示例：
    hx.api_ssyx("1500")
用途：
    根据选择的宿舍价位查询或执行宿舍预选相关操作。
返回示例：
{
    "code":0,
    "msg":"名额已满",
    "data":{
        "remain":0
    }
}
其中：
    msg
        接口返回提示信息。
    data.remain
        当前剩余名额数量。
==================================================
三、统一返回格式说明
所有接口均返回统一结构：
{
    "code":0,
    "status_code":200,
    "msg":"请求成功",
    "is_json":true,
    "data":{}
}
字段说明：
code
    SDK请求状态。
    0：
        请求成功。
    1：
        返回数据不是JSON格式。
    -101：
        请求超时。
    -102：
        请求失败。
    -999：
        未知异常。
status_code
    HTTP响应状态码。
msg
    请求结果说明。
is_json
    判断返回内容是否为JSON。
data
    接口实际返回的数据内容。
==================================================
四、基本使用流程
1. 创建对象
    hx = MicroHX()
2. 设置 Cookies 登录态
    hx.update_auth(cookies)
3. 检查登录状态
    hx.test_auth()
4. 调用业务接口
    hx.api_getvisitedactives()
    hx.api_sumhdxfforxflx()
    hx.api_ssyx("1500")
==================================================
注意：
1. Cookies需要用户自行获取，SDK不会自动登录。
2. Cookies失效后，需要重新调用 update_auth() 更新登录态。
3. 所有接口均基于当前对象保存的 Session 和登录状态进行请求。
